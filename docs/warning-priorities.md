# ESLint 警告处理优先级指南

## 概述

本文档定义了处理项目中 ESLint 警告的优先级策略，帮助团队有计划地减少警告数量。

## 优先级分类

### 优先级 P0 - 立即修复（阻塞发布）

**定义**: 可能导致构建失败或运行时错误的警告

**处理标准**:
- 在合并 PR 之前必须修复
- 不允许合并到主分支

**示例**:
- TypeScript 类型错误
- 可能导致运行时问题的代码
- 核心业务逻辑中的警告

### 优先级 P1 - 高优先级（本周修复）

**定义**: 核心业务组件和频繁修改的文件

**处理标准**:
- 在本周内修复
- 优先处理活跃开发的模块

**目标文件**:
- `src/components/` 中的核心组件
- `src/app/` 中的关键页面
- 频繁修改的文件（Git 统计显示）

### 优先级 P2 - 中优先级（本月修复）

**定义**: 工具函数和 API 路由

**处理标准**:
- 在本月内安排修复
- 可在常规开发过程中逐步处理

**目标文件**:
- `src/lib/` 中的工具函数
- `src/app/api/` 中的路由
- `src/hooks/` 中的自定义钩子

### 优先级 P3 - 低优先级（季度清理）

**定义**: 静态配置和很少修改的文件

**处理标准**:
- 安排在季度清理活动中
- 不影响日常开发

**目标文件**:
- 配置文件
- 类型定义文件
- 测试工具文件

### 优先级 P4 - 长期跟踪（重构时处理）

**定义**: 废弃代码或计划重构的模块

**处理标准**:
- 在重构时统一处理
- 标记为技术债务

**示例**:
- 计划废弃的功能模块
- 即将重构的大型组件
- 临时代码

## 处理策略

### 1. 自动修复优先

```bash
# 先尝试自动修复
pnpm lint --fix

# 检查剩余警告
pnpm lint
```

### 2. 未使用变量处理

**情况 A: 确实未使用**
- 删除变量定义
- 删除未使用的导入

**情况 B: 保留但标记为未使用**
- 添加下划线前缀: `user` → `_user`
- 用于保持 API 一致性的参数

**情况 C: 未来可能使用**
- 添加 `eslint-disable` 注释
- 说明未使用原因

### 3. 批量处理流程

```bash
# 1. 生成当前报告
node scripts/track-eslint-warnings.js

# 2. 查看报告
cat eslint-warnings-report.json

# 3. 选择优先级高的文件处理

# 4. 验证修复
pnpm tsc --noEmit && pnpm lint
```

## 跟踪机制

### 每周报告

GitHub Actions 会在每周一自动运行 `track-eslint-warnings.js`，生成报告并上传。

### 趋势监控

- 每次合并 PR 前检查警告数量
- 确保新代码不增加警告
- 记录警告减少趋势

### 里程碑

- [ ] 500 警告以下
- [ ] 300 警告以下
- [ ] 100 警告以下
- [ ] 0 警告（理想状态）

## 工具和命令

### 查看当前警告

```bash
# 查看总览
pnpm lint

# 查看特定文件
pnpm lint src/components/xxx.tsx

# 查看特定规则
pnpm lint --rule 'no-unused-vars: error'
```

### 生成报告

```bash
# 生成详细报告
node scripts/track-eslint-warnings.js

# 查看历史报告
ls -la eslint-warnings-report-*.json
```

### 阈值检查

```bash
# 检查是否超过阈值
pnpm lint:threshold
```

## 贡献指南

### 提交代码前

1. 运行 `pnpm lint:fix` 自动修复
2. 检查并手动修复剩余警告
3. 运行 `pnpm tsc --noEmit` 确保类型正确
4. 确保不增加新的警告

### 处理现有警告

1. 选择优先级 P1 或 P2 的文件
2. 逐个文件处理警告
3. 提交 PR 时标注清理的警告数量
4. 更新 `eslint-warnings-report.json`

## 最佳实践

### 1. 预防胜于治疗

- 编写代码时避免未使用的变量
- 定期清理代码
- 使用 IDE 自动删除未使用的导入

### 2. 保持一致性

- 遵循团队约定的处理方式
- 优先使用下划线前缀标记未使用参数
- 必要时添加注释说明

### 3. 渐进式改进

- 不追求一次性清理所有警告
- 优先处理高优先级警告
- 在日常开发中逐步减少
