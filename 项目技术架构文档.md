## 🔄 数据流图

### PDF解析流程

```
用户上传PDF
      │
      ▼
┌─────────────────┐
│  前端: File对象  │
└────────┬────────┘
         │
         ▼
┌─────────────────────────────────────────────────────────┐
│  API: POST /api/documents/parse                          │
│  ┌─────────────────────────────────────────────────┐   │
│  │  1. 接收FormData (File + parseType)            │   │
│  │  2. 权限验证 (NextAuth Session)                │   │
│  │  3. 将File转为Buffer                            │   │
│  │  4. 上传到TextIn (uploadFileToTextIn)          │   │
│  └─────────────────────────────────────────────────┘   │
└────────┬────────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────────┐
│  文件上传: uploadFileToTextIn()                         │
│  ┌─────────────────────────────────────────────────┐   │
│  │  POST https://api.textin.com/api/v3/ocr/upload │   │
│  │  Body: FormData {file}                          │   │
│  │  Return: file_id                                │   │
│  └─────────────────────────────────────────────────┘   │
└────────┬────────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────────┐
│  解析策略选择 (根据parseType)                            │
│  ┌─────────────────┐    ┌─────────────────┐             │
│  │  'auto'         │    │  'textin'       │             │
│  │  先TextIn       │    │  强制TextIn     │             │
│  │  失败则Coze     │    │                 │             │
│  └────────┬────────┘    └────────┬────────┘             │
│           │                      │                      │
│           └──────────┬───────────┘                      │
│                      ▼                                  │
│  ┌─────────────────────────────────────────────────┐   │
│  │  TextIn解析: getTextInTableResponse()          │   │
│  │  ┌─────────────────────────────────────────┐   │   │
│  │  │  GET https://api.textin.com/table/...  │   │   │
│  │  │  Return: HTML或JSON表格数据            │   │   │
│  │  │                                           │   │   │
│  │  │  1. 检测数据格式 (HTML/JSON)            │   │   │
│  │  │  2. 如果HTML: parseHTMLTable()         │   │   │
│  │  │     - 解析HTML表格                     │   │   │
│  │  │     - 提取每行数据                      │   │   │
│  │  │     - mapCellsToProduct()              │   │   │
│  │  │  3. 如果JSON: 解析cells数组            │   │   │
│  │  └─────────────────────────────────────────┘   │   │
│  └────────┬────────────────────────────────────────┘   │
└───────────┼────────────────────────────────────────────┘
            │
            ▼
┌─────────────────────────────────────────────────────────┐
│  Coze解析: getCozeResponse() [备用方案]                │
│  ┌─────────────────────────────────────────────────┐   │
│  │  POST https://api.coze.cn/v1/workflow/run      │   │
│  │  Body: {workflow_id, parameters}               │   │
│  │  Return: {products: [...]}                     │   │
│  └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
            │
            ▼
┌─────────────────────────────────────────────────────────┐
│  数据处理 (route.ts)                                     │
│  ┌─────────────────────────────────────────────────┐   │
│  │  1. 字段映射 normalizeProducts()              │   │
│  │     - specs → parameter_description            │   │
│  │     - 统一字段名                               │   │
│  │                                                 │   │
│  │  2. 去重 deduplicateProducts()                 │   │
│  │     - 基于 name + parameter_description        │   │
│  │     - 移除重复产品                             │   │
│  └─────────────────────────────────────────────────┘   │
└────────┬────────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────────┐
│  返回给前端                                               │
│  {                                                       │
│    "products": [                                         │
│      {                                                   │
│        "name": "...",                                    │
│        "model": "...",                                   │
│        "brand": "...",                                   │
│        "parameter_description": "...",                   │
│        "quantity": 1,                                    │
│        "unit": "套",                                     │
│        "unit_price": 0,                                  │
│        "remark": ""                                      │
│      },                                                  │
│      ...                                                 │
│    ]                                                     │
│  }                                                       │
└─────────────────────────────────────────────────────────┘
         │
         ▼
    前端展示
```

## 🎯 技术选型理由

### 为什么选择 Next.js 16？

1. **App Router**: 现代化的路由架构
2. **Server Components**: 减少客户端负担
3. **优秀的性能**: 自动优化和代码分割
4. **丰富的生态系统**: 大量的第三方库支持

### 为什么选择 TypeScript？

1. **类型安全**: 减少运行时错误
2. **更好的IDE支持**: 智能提示和重构
3. **代码可维护性**: 更容易理解大型项目
4. **团队协作**: 清晰的接口定义

### 为什么选择 PostgreSQL + Drizzle ORM？

1. **关系型数据库**: 适合复杂的关联查询
2. **TypeScript优先**: Drizzle提供类型安全的查询
3. **轻量级**: 比Prisma更轻量，性能更好
4. **灵活**: 支持原生SQL

### 为什么选择 Supabase？

1. **一站式服务**: 认证、数据库、存储
2. **实时功能**: WebSocket支持
3. **开源**: 自托管选项
4. **易用性**: 友好的管理界面
